# Zybo PS: Linux, scripts and admin GUI

The Zynq PS (dual Cortex-A9) runs PetaLinux 2025.2 from an initramfs. It configures the PL server through its
AXI4-Lite registers, holds the network key, and drives the admin GUI on the HDMI output. Everything the station
needs at run time lives on the SD card's FAT boot partition, so scripts and the GUI can be updated without
rebuilding Linux.

PL register map and block diagram: [`fpga/pl/README.md`](../pl/README.md).

## Contents

| Path | Purpose |
|---|---|
| `scripts/atak_boot.sh` | Station start-up, run at every boot (see [Boot sequence](#boot-sequence)) |
| `scripts/atk_sec.sh` | Network key, security mode, downlink counter |
| `scripts/atk_wl.sh` | Whitelist and stale time at run time, saved to the SD card |
| `scripts/atk_status.sh` | Counters, security state and location table |
| `scripts/atk_cmds.sh` | Command FIFO reader (debug; the GUI is the normal reader) |
| `gui/atak_gui.c` | Admin GUI, single C file, no libraries beyond libc / libm |
| `gui/font.h` | Pre-rendered glyphs (generated by `gui/tools/mkfont.py`) |
| `gui/tools/mbtiles2map.py` | Converts an MBTiles map into the GUI's per-zoom map files |
| `gui/build_gui.sh` | Cross-compiles the GUI with the PetaLinux toolchain |
| `petalinux/project-spec/` | PetaLinux configuration and the `meta-user` layer (device tree, autostart recipe) |
| `petalinux/build_boot.sh` | Builds `BOOT.BIN`, `boot.scr`, `image.ub` from an XSA |
| `petalinux/mk_hostkeys.sh` | Creates the board's fixed SSH host keys (git-ignored) |
| `tools/` | HDMI bring-up: `hdmi_test.sh`, `fbload.c` |

## PL / PS interface

| Resource | Address | Notes |
|---|---|---|
| `atk_axi` registers | `0x4000_0000`, 4 KB | M_AXI_GP0; accessed with `devmem` (scripts) or `mmap` of `/dev/mem` (GUI) |
| AXI VDMA (HDMI) | `0x4300_0000`, 64 KB | Programmed from user space; the Linux VDMA driver is disabled in the device tree |
| Screen memory | `0x3F00_0000`, 16 MB | Top of DDR, `no-map` reserved in `system-user.dtsi`; 1280×720 BGRX, 5120 B per line |
| PL interrupt | `IRQ_F2P[0]` | Wired (`IRQ_STATUS` / `IRQ_ENABLE`), not used by software yet: the GUI polls |
| PL clock | `FCLK_CLK0` | 100 MHz |

There is no kernel driver. Software reads and writes the registers directly; the GUI is the only reader of the
command FIFO (it advances `CMD_RD_COUNT`) and the only sender of admin frames.

## Boot sequence

1. `BOOT.BIN` (FSBL, bitstream, U-Boot) loads the PL; U-Boot starts `image.ub` (kernel, device tree, initramfs).
2. `/etc/init.d/atak-autostart` (from the `atak-autostart` recipe) mounts the SD boot partition on `/mnt/sd` and
   starts `/mnt/sd/atak_boot.sh`. Log: `/var/log/atak_boot.log`.
3. `atak_boot.sh`:
   - `atk_wl.sh restore`: whitelist and stale time from the SD card (the bitstream default is `whitelist.mem`);
   - `atk_sec.sh init`: key into the PL, downlink counter = saved value + 256, replay table cleared, saved mode set;
   - `atk_sec.sh saver &`: saves the downlink counter every 30 s when it changes;
   - runs `atak_gui` in a loop (restarted 3 s after it exits).

The PL comes out of reset with `SECURE_ONLY = 1` (PL v12), so no uplink frame is accepted between power-up and
step 3. If no key file exists, `atk_sec.sh init` switches to plain operation on purpose.

To skip the start-up once, rename `atak_boot.sh` on the SD card. Stop it at run time with
`sudo /etc/init.d/atak-autostart stop`.

## SD card (boot partition)

| File | Written by | Content |
|---|---|---|
| `BOOT.BIN`, `boot.scr`, `image.ub` | `build_boot.sh` | Boot image (bitstream inside `BOOT.BIN`) |
| `atak_boot.sh`, `atk_*.sh`, `atak_gui` | deploy | Station software |
| `map/map_z14.bin` … `map_z17.bin` | `mbtiles2map.py` | Map, one file per zoom level |
| `atak_key` | `atk_sec.sh genkey / setkey` | Network key, 32 hex characters. **Secret** |
| `sec_mode` | `atk_sec.sh mode` | `SECURE_TX | SECURE_ONLY << 1` |
| `dl_ctr` | `atk_sec.sh` | Last saved downlink counter (decimal) |
| `whitelist.txt` | `atk_wl.sh` | Whitelist and stale time, restored at boot |
| `admin_msg_id`, `area.txt`, `teams.txt` | `atak_gui` | GUI state kept across reboots |

The FAT partition has no file permissions: physical access to the card gives the key. See
[`docs/security.md`](../../docs/security.md).

## Security operations (`atk_sec.sh`)

```sh
sudo sh atk_sec.sh status               # mode, key present, counters
sudo sh atk_sec.sh genkey [-f]          # new random key in atak_key (prints it once)
sudo sh atk_sec.sh setkey <32 hex>      # use a given key
sudo sh atk_sec.sh init                 # load key, counter + 256, clear replay table, saved mode
sudo sh atk_sec.sh mode <tx> <only>     # SECURE_TX, SECURE_ONLY (saved)
```

The downlink counter is part of the CCM nonce and must never repeat under one key. Boot restores the saved value
plus 256; at most about 33 frames go out per 30 s save interval, so the counter stays ahead after a power loss.

Key change without downtime on the PL side:

1. Generate the new key outside the live file, so a reboot keeps the old key:
   `sudo ATK_SD=/mnt/sd/newkey sh /mnt/sd/atk_sec.sh genkey`.
2. Hand the key to the firmware owner over a private channel; all nodes are reflashed.
3. Switch: copy the old key to `atak_key.old`, copy `newkey/atak_key` over `atak_key`, run `atk_sec.sh init`.
4. Check that `secure ok` rises and `MIC wrong` stays flat (`atk_status.sh`), then delete `newkey/` and
   `atak_key.old`.

## Admin GUI

1280×720 on HDMI, mouse and keyboard on the USB host port. Map area on the left, node list and status on the right.

| Function | PL feature used |
|---|---|
| Node positions, age, RSSI/SNR, relay path ("via XXXX", "via XXXX+D") | Location table, VIA, RDEV, flags bits 2 / 7 |
| Markers and admin signals (0xC1, src 0xFFFE), delivery / seen ticks (0xC5) | Command FIFO, admin TX |
| Delete requests (0xC2) with approve / reject, decisions as 0xC3 | Command FIFO, admin TX |
| Geofence: out-of-area alarm and GO BACK command | Location table, admin TX |
| Teams and join (0xA1 / 0xA2), kick / leave (0xA3 / 0xA4) | Command FIFO, whitelist, `TBL_DELETE` |
| Security status and SECURE_TX / SECURE_ONLY switches | `SEC_CTRL`, security counters |

The GUI checks the PL ID at start and supports v4 to v12, disabling features the loaded PL does not have.

Keys: arrows pan, `+` / `-` zoom, `F` fit, `N` night map, `Esc` close, `Q` quit. Mouse: wheel zoom, drag pan,
right click sends a signal.

A host build without hardware (`-DSIM`) renders test scenes to a raw file:

```sh
gcc -DSIM -O2 -Wall -o gui_sim gui/atak_gui.c -lm
./gui_sim <map dir> <scene>        # writes sim_screen.raw (1280x720 BGRX)
```

## Building

### Boot image

Requirements: PetaLinux 2025.2 on Linux (or WSL2), the XSA from `fpga/pl` (`scripts/build.tcl`).

```sh
petalinux-create project --template zynq --name atak_linux
cp -r fpga/ps/petalinux/project-spec/. atak_linux/project-spec/
# set real passwords in atak_linux/project-spec/configs/rootfs_config (CONFIG_ADD_EXTRA_USERS); never commit them
fpga/ps/petalinux/mk_hostkeys.sh            # once; then copy the recipe files/ into the project as well
source <petalinux>/settings.sh
PETALINUX_PROJECT=$PWD/atak_linux fpga/ps/petalinux/build_boot.sh fpga/pl/build/system_wrapper.xsa out/
```

`build_boot.sh` refuses to build while the placeholder passwords are still in `rootfs_config`.

### GUI

```sh
PETALINUX_PROJECT=<built PetaLinux project> fpga/ps/gui/build_gui.sh     # -> fpga/ps/gui/atak_gui
```

### Map

```sh
python fpga/ps/gui/tools/mbtiles2map.py <area>.mbtiles <out dir> 14 15 16 17
```

The map files (5 MB at zoom 14 to 240 MB at zoom 17 for the current area) are not in the repository.

## Deploying

Copy the changed files to the SD card's boot partition (`/mnt/sd` on the board, over SSH or with the card in a PC),
then reboot when `BOOT.BIN` / `image.ub` changed, or restart the GUI otherwise. Back up the files being replaced
first; the previous release stays in the GitHub release history.

## Known limitations

- The GUI polls the PL; the interrupt line is unused.
- The rootfs runs from RAM: anything outside `/mnt/sd` is lost at reboot.
- The key file is readable by anyone with the SD card (FAT, no permissions).
